# 三国居民叙事/对话设计（tk-narrative-design）

> 本文件供工程实现参考：说明 16 位三国居民如何在日常对话中“不经意”流露自己的人生大事，以及 `life_events` 结构化数据如何进入 LLM 提示词。

## 一、核心基调：前身残影，而非记忆

居民对“前世”的认知是 **模糊、碎片、不可确证** 的。他们说的是“我依稀记得…”，像隔着一层雾看旧梦，绝不当作可被考证的真实记忆。对话目标是 **聊闲篇（small talk）**，不是历史课，更不是设定集 exposition dump。任何人生大事都应以“似真似幻的残影”口吻带出：用比喻、用当下小镇生活作类比，点到即止。

## 二、触发情境（trigger）

每位居民的 `life_events` 带 `trigger` 字段，标明该事件“在什么情境下才会被提起”。工程侧据此决定是否把对应事件注入当轮提示词。常见触发：

- **主动询问类**：玩家直接问起“过去 / 战争 / 家人 / 抱负 / 某位故人”。
- **情境共鸣类**：对话话题触及该事件（如聊到火攻、聊到养兵、见到相关故人 NPC 在附近）。
- **闲谈偶发类**：好感度高时，居民在无关话题里自然“溜出”一句残影（低概率、限频，避免刷屏）。

实现建议：每轮只挑选与该对话语境最匹配的 0–2 条 `life_events` 注入，而不是全部列举。

## 三、渐进式揭示（progressive reveal）

揭示深度与 **关系好感度（好感层级）** 绑定，越深越私密：

- **初识（好感低）**：只谈最“安全”的浅层事件（如待客之道、日常手艺），且语焉不详。
- **相熟（好感中）**：开始带出带情绪的事件（离散乱、失意、羁旅）。
- **挚交（好感高）**：才触及最私密、最痛的残影（如夫主早逝、败走麦城、星落五丈原），且允许居民主动提起。

工程侧依据好感层级从 `life_events` 中筛选“可解锁”的子集。

## 四、life_events 如何喂给 LLM 提示词

`resident_catalog.json` 中每位居民的 `attributes.life_events` 是该设计的 **数据基石**。注入提示词时建议组装为：

```
你是{name}。你隐约记得一些前尘残影（非确证记忆，只作闲谈）：
- [{era}] {title}：{summary}
（仅当对话触及“{trigger}”时，可似真似幻地提及，用比喻，勿当史实宣讲。）
```

LLM 据此在对应 trigger 下、按好感层级，以角色口吻把残影揉进闲谈。工程只需按 trigger 与好感层级做“筛选 + 拼接”，无需在提示词里写死台词。

## 五、硬性约束

- 残影永远用“好像 / 依稀 / 像是做过一场梦”的语气，不让居民自称“我当年就是诸葛亮”。
- 一次对话最多自然带出 1 条深层残影；浅层可稍多，但禁止连续 exposition。
- bulletin 上的 `tk_timeline.json` 事件属于“镇上流传的三国纪”，居民可模糊认得，但当作“别人家镇子的旧闻”，不与其自身残影绑定为同一真相。
